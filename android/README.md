# Inno Sport Admin

Нативное приложение модерации для Android 8.0 и новее. Установочный файл: `../releases/InnoSport-Admin.apk`.

## Вход

1. Установить APK на телефон. Android может попросить разрешить установку из выбранного источника.
2. Написать `/moderation` в личном чате @sport_inno_bot с закреплённого аккаунта владельца.
3. Скопировать целиком строку `INNOSPORT|https://…|…` и вставить в приложение.

Код действует 5 минут и используется один раз. Сессия действует 30 минут; после закрытия приложения может потребоваться новый вход. `/modrevoke` отзывает все активные сессии и коды. Команды не включены в общий список команд Telegram.

Приложение использует работающий сервер на ноутбуке. Если ноутбук выключен, сервер остановлен или туннель недоступен, приложение не сможет подключиться. После смены адреса туннеля получить новую строку командой `/moderation`.

## Разделы

- Люди: цели, будущие записи, пауза, отмена записи и удаление цели по просьбе пользователя.
- Функции: общие переключатели бота.
- Базы: bot.sqlite3 и journal.sqlite3, таблицы, поиск и страницы по 50 строк. Значения передаются с сервера без сокрытия полей; зашифрованные значения остаются в том виде, в котором хранятся в SQLite.
- Журнал: последние 30 действий модерации.

Веб-модерация отключена. Все административные API требуют отдельную сессию Android; Telegram initData больше не даёт доступ к этим API. Проверка владельца использует закреплённый числовой ID, без восстановления по username. Коды и токены сохраняются на сервере только в виде SHA-256. Токен бота и базы не включены в APK. TLS проверяется системными средствами; HTTP и перенаправления запрещены. Сессия хранится только в памяти приложения. Резервное копирование Android и снимки экрана отключены.

## Сборка

Запустить `powershell -NoProfile -ExecutionPolicy Bypass -File android/build.ps1` из каталога проекта. Инструменты Android SDK 35 расположены в `.tools/android`, исходники — в `android/src`. Скрипт использует установленный JDK 24; путь задаётся в build.ps1. Официальные инструменты и их NOTICE сохранены в `.tools/android`; архивы сверены с контрольными суммами Google SDK repository.

Ключ подписи и пароль находятся в `data/android-signing`, исключённом из Git. Сохранить эту папку в приватной резервной копии: без того же ключа нельзя установить обновление поверх существующего приложения. Не передавать папку подписи вместе с APK. Перед следующей публикацией увеличить versionCode в AndroidManifest.xml.

APK проходит zipalign и проверку apksigner (v2/v3). Серверный вход проверяется автоматическими тестами, но установку, внешний вид и работу на конкретном телефоне нужно проверить на устройстве.


## Версия 1.1

- «Система»: время работы сервера, доступность Telegram API (проверка не чаще раза в минуту), последний реальный запрос к порталу, состояние планировщика и поиска, последние 20 категорий ошибок текущего процесса. Портал не опрашивается отдельно ради экрана состояния; отсутствие свежих данных не означает доступность. Полные тексты исключений и личные данные в этот экран не передаются.
- «Устройства»: активные сессии, название, время входа/активности/истечения, отзыв каждой сессии либо всех остальных. Название вводится при входе, не является доказательством идентичности устройства. Сессии по-прежнему истекают через 30 минут.
- «Копии»: список, результат проверки SQLite, размер, ручное создание. Автоматическая копия при запуске, если последняя ежедневная старше суток; затем проверка каждые 15 минут. Пропущенные из-за выключенного ноутбука копии выполняются после следующего запуска. Хранится до 14 ежедневных и 10 ручных наборов.

Копии: `data/backups/automatic/<id>`. Каждый набор содержит обе базы, `secret.key`, закреплённый ID владельца и manifest.json с размерами и SHA-256. Копирование использует SQLite backup API, учитывает WAL; каждая база проверяется integrity_check. Набор публикуется после успешного завершения обеих копий. Это отдельные согласованные снимки каждой базы, без общей транзакции между двумя файлами.

Копии содержат приватные данные и ключ расшифровки; не публиковать и не передавать посторонним. Они находятся на том же диске: при поломке диска нужна внешняя копия, например на NAS. Восстановление пока выполняется вручную с остановкой бота и его автоперезапуска, сохранением текущих файлов и проверкой SHA-256. Перед заменой нельзя оставлять старые файлы -wal/-shm. После восстановления нужно очистить moderator_sessions и moderator_pairing, чтобы не восстановить ранее отозванный доступ. Ключ secret.key восстанавливается вместе с соответствующими базами. Из приложения перезапись рабочих баз недоступна.


## Версия 1.2: пользователи и устройства Mini App

«Устройства» показывает пользователей бота и наблюдавшиеся установки обычного Mini App: Telegram ID/username, платформу, user-agent, первое открытие и последнюю активность. Данные устройств появляются после следующего запроса обновлённого Mini App, прошлые устройства восстановить нельзя. Это не список устройств Telegram, не точные модели телефонов и не IMEI. Клиентские сведения не подтверждают аппаратную идентичность.

Для Mini App используется случайный ID в localStorage, привязанный на сервере к проверенному Telegram ID. Очистка данных, другой клиент или смена домена туннеля создают новую установку. Блокировка установки ограничивает только Mini App и может обходиться сменой этого ID; для запрета доступа к боту использовать «Заблокировать в боте» у пользователя. Установки записываются только после проверки подписи Telegram. Сохраняется до 50 установок на аккаунт, IP-адреса не сохраняются.

Блокировка Telegram-аккаунта хранится в SQLite и действует на команды/кнопки бота, все API обычного Mini App, автоматическую запись и напоминания. Изменение username или телефона не снимает блокировку. Блокировка не отменяет уже выполненные записи и не может отозвать запрос, который портал уже получил. При разблокировке сохранённые цели/настройки снова действуют. Владелец защищён от блокировки самого себя. Действия блокировки и разблокировки фиксируются в moderation_audit. Административный APK продолжает отдельно показывать свои сессии в «Входы APK».
