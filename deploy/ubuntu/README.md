# Ubuntu Server на домашнем NAS

Комплект для Ubuntu Server 22.04/24.04/26.04 LTS, архитектуры amd64 или arm64. Docker запускает Python и Chromium внутри Linux-контейнера; графический рабочий стол Ubuntu не нужен. Существующие NAS-контейнеры и настройки дисков установщик не удаляет.

## 1. Подготовить Ubuntu

Подключиться к NAS по SSH. На чистой системе:

```bash
sudo apt-get update
sudo apt-get install -y git python3
git clone https://github.com/AtomicYou/SportBot.git
cd SportBot
sudo bash deploy/ubuntu/install-docker.sh
cp .env.example .env
chmod 600 .env
nano .env
```

Указать BOT_TOKEN и постоянный внешний HTTPS-адрес MINIAPP_URL. Для папки данных по умолчанию оставить SPORTBOT_DATA_DIR=./data. Для локального диска NAS можно указать абсолютный путь, например /srv/sportbot-data. Это должен быть отдельный каталог приложения, а не корень общего хранилища. Не использовать SMB/NFS для рабочих SQLite-баз с WAL; размещать их на локальной файловой системе самого NAS. Отдельные готовые резервные копии можно отправлять на другой носитель.

Установщик использует официальный apt-репозиторий Docker: https://docs.docker.com/engine/install/ubuntu/. При наличии Docker сохраняет его установку; при конфликтующих пакетах останавливается вместо автоматического удаления контейнерной среды. Если существующему Docker не хватает Compose plugin, его нужно установить подходящим для текущей установки способом.

## 2. Сначала перенести данные, если они уже есть

Если сохраняются пользователи с ноутбука, сначала остановить там задачу «InnoSport Mini App» и supervisor. Перенести обе базы из завершённого снимка, исходный secret.key и moderator-identity.json приватным каналом. Подробности: [DEPLOY.md](../../DEPLOY.md). Не запускать ноутбук и NAS одновременно с одним токеном.

У перенесённой папки и файлов должен быть владелец UID/GID 10001. Например, для специально выделенного каталога проекта после проверки пути:

```bash
pwd
ls -ld ./data
sudo chown -R 10001:10001 ./data
sudo chmod 700 ./data
```

Не применять эту команду к общему каталогу NAS. Если SPORTBOT_DATA_DIR указывает на другую папку, проверить её абсолютный путь и настроить права именно для неё. Скрипт запуска существующие права автоматически не переписывает. После восстановления очистить старые сессии модерации по инструкции DEPLOY.md.

## 3. Запустить

```bash
sudo bash deploy/ubuntu/start.sh YOUR_NUMERIC_TELEGRAM_ID
sudo docker compose ps
sudo docker compose logs -f --tail=100 bot
```

Заменить YOUR_NUMERIC_TELEGRAM_ID своим числовым ID Telegram. Существующий закреплённый владелец не заменяется. Скрипт проверяет .env без вывода токена, создаёт новый каталог данных с владельцем 10001, собирает образ, закрепляет владельца и ожидает готовности HTTP-сервера.

После включения NAS Docker поднимает ранее работавший контейнер благодаря restart: unless-stopped и включённой службе docker. Если контейнер был остановлен вручную, он останется остановленным до `sudo docker compose up -d`. При смене/задержке подключения отдельного диска NAS сначала обеспечить его монтирование, затем запускать Docker: приложение не должно создать пустую папку вместо отсутствующего диска. Зависимость от конкретной точки монтирования настроим после получения структуры NAS.

Проверка healthcheck означает доступность HTTP-сервера, а не успешную авторизацию Telegram/портала. При статусе unhealthy смотреть журнал: Docker сам по себе не перезапускает контейнер исключительно из-за этого статуса. Аварийное завершение процесса перезапускается политикой restart.

## 4. HTTPS для Mini App и APK

API слушает 8082 внутри контейнера; на NAS опубликован только 127.0.0.1:8082. Подключить HTTPS-прокси или туннель к этому адресу и указать тот же адрес в MINIAPP_URL. Домен, сертификат и выбранный туннель настраиваются после получения доступа к NAS. Никакие порты роутера установщик не открывает.

Изменения .env применяются командой:

```bash
sudo docker compose up -d --force-recreate
```

Проверить /app, /moderation, расписание и вход. APK получает новый адрес через свежую строку /moderation; его не требуется пересобирать для смены сервера. Windows EXE-монитор остаётся программой ноутбука и локальные файлы NAS автоматически не читает.

## Обслуживание

```bash
sudo docker compose logs -f --tail=100 bot
sudo docker compose restart bot
sudo docker compose down
# Обновление после создания резервной копии:
git pull --ff-only
sudo docker compose up -d --build --wait --wait-timeout 180
```

Данные сохраняются отдельно от контейнера. Автоматические копии: SPORTBOT_DATA_DIR/backups/automatic. На новом сервере отдельно проверить доступность api.telegram.org и спортивного портала: установка Docker не снимает сетевые ограничения провайдера.

Скрипты и конфигурация проверены локально без установки Ubuntu. Полная сборка образа, запуск Chromium и перезагрузка NAS будут проверены на самом сервере после предоставления доступа.
